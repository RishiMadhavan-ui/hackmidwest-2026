The original matrix's NOT_RUN cells remain a specification snapshot. The statuses
below are current evidence, assessed against each case's actual level and scope.
**PASS is only the stated tested scope/environment, not blanket product readiness.**
Related passing tests do not pass an unimplemented full case. NOT_RUN means a
candidate/partial test exists but acceptance has not been fully exercised; MISSING
means the full capability/test is absent. BLOCKED_EXTERNAL names actual runtime/
provider prerequisites and does not excuse missing application code.

Implementation labels: IT = implemented and tested in the listed scope;
IU = implemented but untested; PI = partially implemented;
M = missing; BC = blocked by external configuration; UV = unknown/unverified.
No label here infers a feature merely from a file/interface/dependency.

## Reproduction and evidence

Use each service's locked Python 3.12 environment. No shared .env, deployed DB,
provider secrets or live customers are used. Commands are PowerShell from repo
root unless a working directory is named. Full suite evidence is in
[V2_TEST_RESULTS.md](V2_TEST_RESULTS.md); E_* links are recorded there with commands,
actual output and execution date, including latest main integration outputs. Tests marked related-only need the specified
additional setup/behavior before their case can pass.

- T_API: set LEASH_TEST_DATABASE_URL to disposable localhost leash_test* DB;
  set LEASH_TEST_VALKEY_URL to redis://127.0.0.1:56379/15 and LEASH_TEST_STACK=1,
  build web first; `api/.venv/Scripts/python.exe -m unittest discover -s api/tests -v`.
  E_API is unit/mocked HTTP plus real PostgreSQL/HTTP, with a real local Next/rail/
  Redis/store smoke. Grants and confirmation predicates in unit fixtures are
  explicitly seeded; Lithic mocked. No real model/provider integration.
- T_RAIL: named services/webhook directory; LEASH_TEST_VALKEY_URL as above;
  `.venv/Scripts/python.exe -m unittest discover -s tests -v`. E_RAIL covers memory
  and isolated real Redis Lua/atomic account latch, local HTTP and mocked ASA.
  No run generations, genuine merchant charging or signed live provider traffic.
- T_STORE: services/store directory; `.venv/Scripts/python.exe -m pytest -q`.
  E_STORE is simulated catalog/TestClient, process-memory checkout, no real charge.
- T_AGENTS: services/agents directory; uv on PATH;
  `.venv/Scripts/python.exe -m pytest -q -m 'not live'`. E_AGENTS is scripted model,
  mocks and genuine local MCP SDK transport; live inference tests skipped.
- T_MCP_LEASH / T_MCP_STORE: respective services/mcp-* directory;
  `.venv/Scripts/python.exe -m pytest -q`. E_MCP_* uses SDK tool clients and mocked
  backend/store; does not imply financial authority or live inference.
- T_DECISION: `services/webhook/.venv/Scripts/python.exe -m unittest discover -s tests -p test_decision_cases.py -v`.
  E_DECISION runs the independent 16 YAML policy/handler cases.
- T_E2E: existing gated `tests/e2e/` needs isolated full API/agents/store/rail,
  mode-separated owned bindings, confirmed mandates and opt-in configuration.
  E_E2E records actual skipped collection. Do not enable against a shared demo
  or claim a manual second-run fixture is automatic Graph recovery.
- Missing Graph/recovery/stop integrations require the H14 scope/generation
  contract, real SDK Graph and owning leased workers. Provider cases require
  confirmed sandbox SINGLE_USE eligibility, ASA enrollment/HMAC/HTTPS/correlation.
  Kubernetes cases require approved isolated staging access, actual image/source
  revisions, TLS/CNI/PVC/Secret references; never wipe production Valkey for tests.

The planned targets in rows are handoff locations, **not existing Python files or
functions**. Owners should extend grouped existing suites when practical and tag
the case IDs, avoiding 137 redundant implementation-mirroring test functions.
Infra/E2E targets are Aditya-owned scenarios coordinated with Cameron; API/payment
targets follow AGENTS path ownership even where multiple humans implement the
dependent feature. Contract changes need a dedicated agreed PR; this index is not
that approval. Full-case rows must include original/generation/checkout/card/run
bindings and actual outcome assertions, not merely an HTTP success code.
